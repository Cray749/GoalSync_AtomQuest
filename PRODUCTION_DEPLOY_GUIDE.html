P PART A — Bug Fixes (Apply Before Deploying)

Apply all 4 fixes to your local codebase first, then push to GitHub. Deploying with these bugs means your demo will crash in front of judges.

🔴 Fix 1 — CSV Export Crash (Critical)

File: server/src/controllers/reports.controller.js

⚠️
Runtime crash on "Download CSV"

json2csv v6-alpha removed the synchronous Parser class. Your code uses the v5 API. This throws TypeError: Parser is not a constructor the moment any user clicks Download CSV.

Change 1 of 2 — top of file (line ~6)

// ❌ REMOVE this line:
const { Parser } = require('json2csv');

// ✅ REPLACE with:
const { parse: csvParse } = require('json2csv');

Change 2 of 2 — inside the CSV export helper (lines ~256–257)

// ❌ REMOVE these two lines:
const parser = new Parser();
const csv    = parser.parse(data);

// ✅ REPLACE with one line:
const csv = csvParse(data);
✓

No package reinstall needed. Same json2csv@6-alpha package, just the correct v6 API call.

🔴 Fix 2 — Shared Goal Achievement Sync (Critical)

File: server/src/controllers/achievements.controller.js

The BRD says: "Achievement updates by the primary owner sync across all linked goal sheets." Right now when Aarav logs Q1 actuals on a shared goal, Meera's linked copy stays blank. Add the cascade block in both createAchievement and updateAchievement.

In createAchievement — add after the main upsert, before the "Notify manager" comment

// ── Cascade actuals to shared-goal children (BRD §2.1) ───────
// Only the primary owner (no parent_goal_id) triggers cascade.
if (!goal.parent_goal_id) {
  const { rows: children } = await query(
    `SELECT id FROM goals WHERE parent_goal_id = $1 AND status = 'approved'`,
    [goal_id]
  );
  for (const child of children) {
    await query(`
      INSERT INTO goal_achievements
        (goal_id, quarter, planned_value, actual_value, completion_date, goal_status)
      VALUES ($1, $2, $3, $4, $5, $6)
      ON CONFLICT (goal_id, quarter) DO UPDATE SET
        actual_value    = EXCLUDED.actual_value,
        completion_date = EXCLUDED.completion_date,
        goal_status     = EXCLUDED.goal_status,
        submitted_at    = NOW(),
        updated_at      = NOW()
    `, [
      child.id, quarter,
      goal.target_value ?? null,
      actual_value      ?? null,
      completion_date   ?? null,
      goal_status       ?? 'not_started',
    ]);
  }
}

In updateAchievement — same cascade block, add after the main UPDATE query

Find the UPDATE statement in updateAchievement, and paste the identical cascade block right after it. Replace goal_id with ach.goal_id (use whatever variable holds the parent goal row's id in that function).

B PART B — Production Hardening

Backend Changes

1. Remove dotenv from production — server/src/server.js

Render injects environment variables natively. dotenv in production is harmless but cluttered. Wrap it so it only loads locally:

// server/src/server.js — line 6, CHANGE:
require('dotenv').config();

// TO:
if (process.env.NODE_ENV !== 'production') {
  require('dotenv').config();
}

2. Add trust proxy — server/src/app.js

Render sits behind a load balancer. Without this, express-rate-limit sees the proxy IP for every request and throttles everyone together.

// server/src/app.js — add immediately after `const app = express();`
app.set('trust proxy', 1); // Trust first proxy (Render's load balancer)

3. CORS — add your Render frontend URL

Your current CORS array only allows CLIENT_URL. On Render, set this env var after deployment, but also add your known Render subdomain as a fallback. Find the allowedOrigins array in app.js:

const allowedOrigins = [
  process.env.CLIENT_URL || 'http://localhost:5173',
  'http://localhost:5173',
  'http://localhost:3000',
  // ADD THESE after you know your Render frontend URL:
  // 'https://goalsynce.onrender.com',
];
// You'll uncomment the last line after Step 3 of the Render deploy.

4. Add a /ready endpoint — server/src/app.js

Render uses health checks. Your existing /health is fine, but a /ready endpoint that checks DB connectivity is more robust:

// Add after the existing /health route in app.js:
app.get('/ready', async (_req, res) => {
  try {
    const { pool } = require('./config/db');
    await pool.query('SELECT 1');
    res.json({ status: 'ready', db: 'ok' });
  } catch (err) {
    res.status(503).json({ status: 'not ready', db: err.message });
  }
});

5. Verify render.yaml (Render's build config)

Your current nixpacks.toml works on Railway but Render uses its own system. Create server/render.yaml at the repo root level instead:

# render.yaml — place at REPO ROOT (not inside /server)
services:
  - type: web
    name: goalsynce-api
    runtime: node
    rootDir: server
    buildCommand: npm ci
    startCommand: npm start
    healthCheckPath: /health
    envVars:
      - key: NODE_ENV
        value: production
ℹ

Render auto-detects Node.js from package.json. The render.yaml just makes the settings explicit and reproducible. You can also configure everything through the Render dashboard — the YAML is optional but recommended.

Frontend Changes

1. vite.config.js — remove the dev proxy from build

The proxy config is dev-only. It's already inside server: {} so it won't affect the production build. No change needed — just confirming it's safe.

2. Add a _redirects file for Render Static Sites

Render Static Sites use a _redirects file (not vercel.json). Create client/public/_redirects:

/* /index.html 200

This is the Render equivalent of your existing vercel.json SPA rewrite. Without it, any direct URL like /employee/goals returns a 404 on page refresh.

Your client/src/services/index.js already uses:

D PART D — GitHub Setup & Auto-Deploy

GitHub Repository Structure

Push the entire monorepo as a single GitHub repo. Render's rootDir setting handles pointing to the right subfolder for each service.

goalsynce/ # GitHub repo root ├── .gitignore # Root gitignore (add this) ├── render.yaml # IaC for Render (add this) ├── README.md ├── server/ # Backend — Render rootDir: server │ ├── .gitignore │ ├── src/ # (all your source files) │ ├── migrations/ │ ├── scripts/ │ ├── package.json │ ├── Procfile │ └── render.yaml # optional, can use root-level one └── client/ # Frontend — Render rootDir: client ├── .gitignore ├── public/_redirects # CRITICAL: add this file ├── src/ ├── package.json └── vite.config.js

First push commands

# From your project root folder:
git init

render.yaml — Infrastructure as Code

Create this file at the repo root. Once you have it, you can tear down and recreate your entire Render setup with one click ("Blueprint" deploy in Render).

# render.yaml — place at REPO ROOT
databases:
  - name: goalsynce-db
    plan: free
    region: singapore

services:
  - type: web
    name: goalsynce-api
    runtime: node
    rootDir: server
    plan: free
    region: singapore
    buildCommand: npm ci
    startCommand: npm start
    healthCheckPath: /health
    envVars:
      - key: NODE_ENV
        value: production
      - key: DATABASE_URL
        fromDatabase:
          name: goalsynce-db
          property: connectionString
      - key: JWT_SECRET
        generateValue: true  # Render generates a random secret
      - key: CLIENT_URL
        value: https://goalsynce.onrender.com
      - key: JWT_EXPIRES_IN
        value: 8h

  - type: web
    name: goalsynce
    runtime: static
    rootDir: client
    plan: free
    region: singapore
    buildCommand: npm ci && npm run build
    staticPublishPath: dist
    envVars:
      - key: VITE_API_URL
        value: https://goalsynce-api.onrender.com/api
    routes:
      - type: rewrite
        source: /*
        destination: /index.html
✓
The routes block in render.yaml replaces _redirects

If you have the render.yaml with the routes section, you don't need the public/_redirects file separately. Either one works — both is also fine (no conflict).

Once your GitHub repo is connected to Render, every push to main triggers auto-deploy. This is on by default. The flow is:

git push origin main

GitHub webhook fires
→
